# v0.8 PROGRAM/GVL deterministic PLC execution

User authorized implementation, .TcGVL import, tests and conveyor example. Python>=3.11,
stdlib-only runtime, Linux, no TwinCAT installation. Baseline1745tests. No Git repository.

## Approach
Extend existing parser, validator and sequential Engine. PROGRAM has one persistent frame per
name per Runtime; GVL has one shared frame per list per Runtime. Reuse existing Cells and
constant/type validation; do not implement scheduler threads or native TwinCAT binaries.
Alternatives considered: METHOD/OOP would cover OO libraries, but user selected PROGRAM/GVL
integration testing; scheduler and full-project loading would unnecessarily enlarge scope.

## Shared AST/registry interfaces (binding between workers)
- syntax.GlobalVarList(name:str, variables:tuple[VarDecl,...], loc:Location,
  qualified_only:bool=False), frozen. Canonical names uppercase like existing AST.
- syntax.Program(pous, types=(), gvls=()) gains trailing defaulted tuple field, preserving
  positional callers. GVL VarDecl.section is VAR_GLOBAL; constant flag from syntax.
- parse(text, source='<string>', *, locations=None, gvl_name='GVL') allows PROGRAM and a
  single named GVL made of all top-level VAR_GLOBAL [CONSTANT] sections in that source.
  Multiple sources give multiple named lists; name is metadata, not invented ST syntax.
- Registry stays dict[str,Pou], and includes synthetic kind='GVL' Pou entries for globals
  with normalized VAR sections and empty body (reuse declaration/default machinery).
  Registry.global_lists: dict[str,bool] maps GVL name -> qualified_only.
  Registry.global_variables: dict[str,tuple[str,...]] maps each unqualified visible variable
  name -> GVL candidates, excluding qualified_only lists. This index includes constants/FBs.
  Registry types/builtin_calls/bit_accesses contracts unchanged.
- Engine.global_frames and Engine.program_frames hold persistent Frames, owned by Runtime.
  Static and runtime name resolution follow the same rules below; do not cache ephemeral
  reference ids without retaining corresponding AST nodes.

## Syntax and loading
- PROGRAM <name> ... END_PROGRAM; allowed sections VAR/VAR CONSTANT/VAR_INPUT/VAR_OUTPUT/
  VAR_TEMP. No return type or VAR_IN_OUT on PROGRAM. PROGRAM cannot be a variable type.
- PROGRAM in .TcPOU, with same strict XML and metadata checks as functions/FBs.
- .TcGVL structure: TcPlcObject/GVL(Name,Id optional)/Declaration text-only. Root existing
  Version/ProductVersion metadata accepted; exactly one GVL and one Declaration. Name
  required and a valid ST identifier. Reject DTD/entities, wrong nodes/attributes, executable
  body, nested XML, extra POU/TYPE declarations, malformed/unknown attributes.
- .st files containing VAR_GLOBAL use filename stem as list name. from_source defaults GVL,
  with optional keyword gvl_name to choose it; parse can mix POU/TYPE/GVL declarations.
- {attribute 'qualified_only'} accepted only immediately before first VAR_GLOBAL section;
  applies to whole list. Unknown pragmas reject rather than ignore. Preserve source locations.
- Multiple GVL names and POU/type names must be unique across namespaces; duplicates reject.
  Two lists may have same variable name. No arbitrary source/project scanning/import.

## Name resolution and shared memory
- Locals (including function result) shadow global identifiers, including namespace names.
- Otherwise GVL.Name resolves explicitly; PROGRAM.Name accesses persistent program state.
- Unqualified variables search non-qualified_only lists: exactly one match resolves; more
  than one is ambiguous and fails validation; none is unknown. qualified_only globals are
  accessed explicitly even from within their own list's initializers.
- Mutable GVL variables can be all currently supported VALUE types (incl structures/arrays),
  and ordinary nonconstant FB instances. Exposed FB members keep existing INPUT/OUTPUT-only
  policy. GVL FB calls use same persistent instance across all callers.
- All global accesses in FUNCTION, FB and PROGRAM observe the same storage. Each Runtime
  owns independent storage. Existing explicit FUNCTION/FB calls can use globals too.
- PROGRAM VAR/INPUT/OUTPUT/CONSTANT can be referenced with Program.Name; external VAR_TEMP
  access rejects. No PROGRAM/GVL whole-value assignment or namespace passing as IN_OUT.
- Global/local/program constants are read-only through any nested path and output/IN_OUT
  binding. Global constants support existing constant expressions and qualified references
  to other global constants (and unqualified lookup under the above rules), including type
  ARRAY/STRING bounds and CASE labels. Initializers may depend on constants, not mutable
  state or calls. Resolve independent of file order; reject cross-list cycles before
  allocating aggregate defaults; preserve existing size/depth limits and preflight projections.

## PROGRAM calls and lifecycle
- Runtime initialization allocates each GVL/program exactly once without executing bodies.
  Initial values resolved/checked by validator; VAR_TEMP reset on every program invocation.
- PROGRAM and FB bodies may call PROGRAM by name with named INPUT/OUTPUT arguments;
  omitted inputs retain values. No return value, cannot appear in expression. FUNCTION
  cannot directly call PROGRAM. Existing static recursion detection includes new call edges.
- Runtime.instantiate remains FB-only, Runtime.call remains FUNCTION-only.
- Existing advance_time changes only time, never executes anything.

## Public Python API and memory
- Runtime.from_source(..., gvl_name='GVL') forwards the naming metadata.
- Runtime.global_cell(gvl_name, variable_name)->Cell and program_cell(program_name,
  variable_name)->Cell expose live typed top-level VALUE storage. Nested field/element/bit
  access uses existing Cell API. FB-valued entries reject as not value cells. Program TEMP
  unavailable. Unknown/type-invalid names -> ArgumentError, not runtime fault.
- Add Cell.read_only property and constructor read_only=False keyword (backward compatible).
  Propagate flag to nested children/bit views. Public writes to read-only cells -> ArgumentError;
  runtime rejects such cells passed as IN_OUT atomically. Internal writes use ExecutionError.
  Reads and acquiring value-cell handles remain allowed after runtime fault for diagnostics;
  writes/new execution still fail via existing fault policy.
- Runtime.scan(*programs:str)->None: require at least one valid unique PROGRAM name (case
  insensitive), validate all names before executing any. Execute in supplied order at same
  now_ms, one shared Context/step budget per scan including nested calls. No time advance.
- Runtime.run_cycles(*programs:str, cycles:int, period_ms:int)->None: validate all args before
  mutation; exact int not BOOL, cycles>=0, period_ms>0. Repeat scan; advance time once AFTER
  each successful whole cycle. cycles=0 validates names/args then no-op. No sleeping/thread.
  New shared Context/budget each cycle. At initial t=0, scans in run_cycles(...cycles=101,
  period_ms=10) see times0..1000 and final clock1010. TON PT1s triggered in first scan goes
  true in the101st scan. Duplicates/empty sequences/non-string names reject atomically.
- If execution fails: retain already-made writes, fault Runtime, skip remaining programs,
  do not advance time for failed cycle; earlier successful cycles keep their time advances.

## Scope exclusions
No multi-rate scheduling/OS realtime, reset/retain/persistence, I/O address mapping/AT,
EtherCAT/ADS, full .plcproj import, methods/properties/interfaces/inheritance, VAR_EXTERNAL.
No changes to existing arithmetic/timer/string profiles.
