# v0.10 Arrays Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** Test groups of FB instances and generic array-processing ST without TwinCAT.
**Architecture:** Distinct FB-array storage, actual fixed Cell bindings for open parameters, and generalized indexed call receivers. Static validation precomputes bound/method dispatch and checks allocation costs.
**Tech Stack:** Python>=3.11 stdlib, pytest, Ruff/reviewdog.
**Spec:** docs/superpowers/specs/2026-10-27-v010-arrays-design.md

## Global Constraints

- Python>=3.11, no runtime dependencies, Linux-compatible, preserve v0.9 behavior.
- Use exact shared interfaces in the spec; assigned files only. Validation/runtime may proceed independently after foundation lands.
- No Git repo: snapshots and diffs replace commits/worktrees. Preserve baseline .work/v010-arrays/baseline.
- Unsupported constructs fail explicitly at load time; Python selection/argument errors do not mutate or fault.

## Review Focus

- Indexed receiver evaluated once before side-effecting arguments; not re-evaluated for type/result lookup.
- Open-array forwarding retains exact original bounds/Cell aliases; rank/type mismatch fails before mutation.
- Array multiplication, nested FBs and containment cycles cannot bypass storage/instance limits.
- Constant-bound/STRING-capacity preflight retains scope and never allocates unresolved arrays.
- Instance handles survive scans; ephemeral VAR_TEMP cannot leak through Python selection.
