# v0.9 FB Methods Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox syntax for tracking.

**Goal:** Execute and test METHOD-based FBs from ST/TcPOU and Python.
**Architecture:** Nested immutable method syntax, owner-qualified validated scopes, explicit owner-linked invocation frames and prevalidated dispatch metadata.
**Tech Stack:** Python >=3.11, stdlib runtime, pytest, Ruff/reviewdog.
**Spec:** docs/superpowers/specs/2026-10-27-v09-methods-design.md

## Global Constraints

- Python >=3.11, standard-library-only runtime, standalone Linux-compatible execution. Preserve v0.8 behavior.
- All methods are statically validated, even unused; unsupported constructs fail explicitly.
- No Git repository is present; retain a baseline snapshot and patch for review, no commits or worktrees.
- Keep edits within assigned files. Independent validation/runtime work may proceed after shared syntax lands.

## Review Focus

- Constant-bound type resolution in method scope must respect local shadowing and qualified owner constants.
- Cross-method aliases and partial failures must preserve existing Cell and runtime fault contracts.
- Method XML cannot smuggle declarations into implementation or drop semantic children.
- Bare calls and method result names must resolve correctly despite globals and similarly named methods.
- Static recursion graph must distinguish FB-body execution from methods and local instance allocation.
