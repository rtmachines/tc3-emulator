# v0.11 Properties Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox syntax for tracking.

**Goal:** Execute FB properties, THIS^ and persistent method variables from ST and Python.
**Architecture:** Extend immutable syntax and strict XML loading first; resolve implicit accessor calls in validation and execute them against the existing FB owner. Allocate VAR_INST with owner storage, preserving fresh method invocation frames.
**Tech Stack:** Python >=3.11, stdlib runtime, pytest, Ruff, reviewdog.
**Spec:** docs/superpowers/specs/2026-10-27-v011-properties-design.md

## Global Constraints

- Runtime stays standalone, Python >=3.11, standard library only, Linux usable and deterministic.
- Preserve v0.10 behavior and existing examples.
- Expanded owner limits: 10,000 nested FB instances and 1,000,000 scalar leaves.
- No repository Git metadata exists: use .work/v011-properties/baseline and immutable review patches; no commits/worktrees.
- User has authorized this bounded implementation; proceed through verification without another approval gate.

## Review Focus

- Indexed property receiver evaluated once before an RHS that mutates its index (Task 2).
- A private accessor cannot be reached via THIS^, implicit calls or Python from an unauthorized scope (Task 2).
- VAR_INST FB child cycles and multiplied ownership budgets fail before allocating (Task 2).
- Property declaration/implementation XML cannot inject another object or hide executable statements (Task 1).
- Failed getter preserves partial state but blocks further execution; inspect never calls getters (Task 2).
